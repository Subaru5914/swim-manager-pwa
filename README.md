## 世界大会と日本代表

世界大会は2027年から隔年（2027・2029・2031…）、8月第2週後半に開催します。その年の3月日本選手権で選考します。ゲームの年度は4月始まりなので、2027年3月の選考は「2026年度」、同年8月の世界大会は「2027年度」です。

個人種目は、日本選手権A決勝のタイムが派遣標準以下の選手のうち上位2名を自動選出します（標準との同タイムを含む）。予選PBや大会前PBだけでは選考されません。フリーリレーは100mFr・200mFrの決勝上位4名、メドレーは100mBa・Br・Fly・Frの各優勝者を選出します。同じ選手が複数泳法で優勝した場合は専門泳法を優先し、それ以外の泳法は決勝2位を選出します。200m専門でも同じ泳法の100m区間を優先します。専門泳法で優勝していない場合は背泳ぎ・平泳ぎ・バタフライ・自由形の順で最初の優勝種目を担当し、2位の選手も重複するなど4名を編成できない場合は出場しません。個人種目の派遣標準はリレー選考には適用しません。

代表情報と選考時の選手情報を保存するため、4月の年度更新や卒業後も代表枠を保持します。4月第1週前半の練習後に代表一覧と祝いの言葉を表示します。世界大会は日本代表を自動登録し、手動で選手やリレーを変更する操作はありません。自チームの選手、または自チームから選出された卒業生が出場する個人予選・決勝を映像で表示します。日本代表リレーも該当選手が1名でもいれば映像を表示します。その他の種目は結果表のみで、全12種目と3リレーの予選総合・決勝結果を確認できます。大学のメンバー以外を含む代表リレーは自大学リレーの歴代10傑へ加えません。

世界大会の予選は50m・100mが4組、200mが3組、400mが2組で、予選総合上位8名が決勝へ進みます。海外は24か国の架空選手を大会年ごとに生成し、同じ大会年の再読込では同じ選手を維持します。個人種目は国ごとに種目専門の2名、リレーは各泳法に合う4名です。海外選手を国内大会のCPU名簿へ混ぜず、日本代表枠は海外エントリー数を調整して確保します。

海外選手は日本選手権のCPUより高い水準で生成します。福岡世界水泳2023の男子・長水路の公式優勝記録を個人12種目・リレー3種目の生成基準に用います。基準に国ごとの水準と個人差を加えて能力を調整し、実際のレースは自チーム・国内CPUと共通の能力計算・乱数・物理処理を使用します。能力188の日本記録基準を維持し、能力200の端点は従来の日本記録99％と参照世界大会優勝記録の速い方を用います。世界大会の強豪はS相当を含みますが、自チーム・国内CPUの生成と成長抑制は引き続きSを希少に保ちます。

## v1.26 の変更

- 確率加入する逸材候補は、各能力の上限を151〜158の範囲でランダムに設定。入学時に既に高い能力を持つ候補にも適用します。
- 練習は能力が高いほど伸びにくくなり、B・A・Sへ進むにつれて成長量が減ります。
- 重点指定がある場合は該当能力を直接練習します。泳法内の副次成長は30％の確率で、重点外のスピード・スタミナ・ターンのうち1項目に発生します。副次成長が発生しないターンもあります。
- 選手詳細で、能力名とランクの間を6px、PBの種目名とタイムの間を8pxに詰めました。文字サイズは維持しています。
- 肩書のない高校生は、低評判でも35〜55％程度のスカウト成功率があります。能力・タイムと大学の評判で変動し、インターハイの肩書を持つ候補は従来どおり難しくなります。
- CPU生成を調整してSランクを希少にし、個人種目・リレーのタイム計算を自チームと共通にしました。CPUだけのタイム上限・大会別補正は廃止しています。
- 物理シミュレーションの刻み幅による誤差で能力基準を超える速い記録が出ないよう、結果・ラップ・再生時間を共通の能力基準へ合わせています。リレーの引き継ぎによる反応時間の短縮は維持します。
- Service Workerのキャッシュをv1.26へ更新しました。

## 能力とタイムの基準

12種目で、種目ごとのスピード・スタミナ・ターン・スタートの比重を維持してタイムへ換算します。代表値は各ランクの中央付近で、関係する能力が揃っている場合の目安です。専門能力が偏る場合やレース時の乱数・メンタルによって、実際のタイムや順位は変動します。

| ランク | 能力 | 目安 | 100mFrの代表基準 |
| --- | --- | --- | --- |
| C | 101〜125 | 関西カレッジ決勝 | 能力113で51.71秒 |
| B | 126〜150 | インカレ決勝 | 能力138で49.50秒 |
| A | 151〜175 | インカレ優勝 | 能力163で48.76秒 |
| S | 176〜200 | 日本記録 | 能力188で47.87秒 |

Bの基準は既存のインカレA決勝参照記録を使用しています。Cの基準は既存の関カレ優勝目安から2％遅く、Aの基準はBから1.5％速く設定したゲーム内の目安で、新しい公式大会記録ではありません。能力200付近では日本記録をわずかに上回る設計です。

施設Lv.100・1項目への重点練習・成長係数1・合宿外の8ターンを500回ずつ試行した平均です。

| 138（B） | 約10.6 |

開始能力80の施設別の8ターン平均は、Lv.0で約8.6、Lv.25で約15.4、Lv.50で約20.8、Lv.75で約25.7、Lv.100で約30.0です。

## セーブの互換性とPWA更新

既存セーブを引き続き読めます。自チームの獲得済み能力・PB・大会履歴・卒業生の能力は維持します。旧バージョンで生成済みの一般CPU選手の能力・初期PBは、最初の読込時に一度だけ新しい基準へ調整します。CPUの肩書に残る実大会記録は保持します。

更新済みの公開URLへオンラインでアクセスし、ゲームを閉じて開き直してください。v1.32のService Workerが準備できると旧キャッシュは削除され、更新版もオフラインで遊べます。PC・iPhoneの自動同期には[Firebaseの設定](./CLOUD_SYNC_SETUP.md)と同じアカウントでのログインを行ってください。

## 開発と検証

ビルドやアプリ用パッケージのインストールは不要です。リポジトリのルートでHTTPサーバーを起動してください。

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

数値・ルール・レース計算・セーブ移行のテストはNode.jsだけで実行できます。

```bash
node --test tests/balance.test.cjs tests/meets.test.cjs tests/cloud.test.cjs
```

表示間隔・右揃え・1項目限定の練習・参加標準の判定、国内大会・世界大会・代表選考の画面操作、旧PWAキャッシュからの更新・オフライン再起動のテストは、PlaywrightとChromiumが利用可能な開発環境で実行します。クラウド環境には両方が導入済みです。

```bash
node --test tests/browser.test.cjs
```

Chromiumの場所は `CHROMIUM_PATH` で指定できます（既定値 `/usr/bin/chromium`）。実機iPhone / Safariでの最終確認は別途必要です。
